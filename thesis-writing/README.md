# כתיבת התזה עם Claude Code

שני skills, חלוקה פשוטה:

| skill | תפקיד | משנה את התזה? |
|---|---|---|
| `/section` | **כותב**: תוכנית לתת-פרק, פסקאות, ויישום ממצאים שבחרתי | כן, רק מה שביקשתי |
| `/thesis-check` | **בודק**: כללים, משלב, בהירות, זרימה, ציטוטים, התאמה לפרק, בניית PDF | לא, אף פעם |

שניהם מצייתים ל-`CLAUDE.md` של תיקיית התזה: אנגלית בריטית, בלי נקודה-פסיק, גוף שלישי, ציטוטים רק ממפתחות שקיימים ב-`bibliography.bib`, וכללי הבהירות שנגזרו מההערות של חזי.

## הסוכנים מאחורי הקלעים

| סוכן | משמש את | מה הוא עושה | מודל |
|---|---|---|---|
| `section-planner` | `/section plan` | מפת דרכים מהצ'אט לקובץ תוכנית | Fable 5 |
| `paragraph-writer` | `/section write`, `apply` | כותב או משכתב פסקה אחת | Fable 5 |
| `thesis-style-reviewer` | `/thesis-check deep` | משלב, בהירות וזרימה, בקריאה אחת | Opus 5.5 |
| `citation-verifier` | `/thesis-check cite` | איפה כל טענה מופיעה במאמר, והאם היא נתמכת | Fable 5 |
| `flow-reviewer` | `/thesis-check fit` | איך תת-הפרק משתלב בפרק ובתזה | Fable 5 |
| `citation-finder` | `/thesis-check needcite` | מקור מ-Papers לכל NEEDCITATION | Fable 5 |

אם מודל לא זמין או מסרב, הסוכן עובר פעם אחת למודל החלופי ומודיע על כך.

## מחזור עבודה על תת-פרק

### 1. מפת דרכים בצ'אט

פותחים את תיקיית התזה ב-Claude Code ומדברים על תת-הפרק כמו תמיד. כשמגיעים להסכמה:

```
/section plan ssec:PrS_Method
```

נוצר `plans/ssec_PrS_Method.md`. לכל פסקה: טענה אחת, ראיה, מקורות מה-bib או NEEDCITATION, ומעבר לפסקה הבאה.

### 2. כתיבה

```
/section write ssec:PrS_Method 1
/section write ssec:PrS_Method 1 "קצר יותר, פתח עם הפער בספרות"
/section write ssec:PrS_Method all
```

- כל פסקה נכתבת תחת שורת הערה `% [P1] כותרת`. היא לא מופיעה ב-PDF. **לא למחוק את העוגנים.**
- הערה בגרשיים משכתבת רק את הפסקה הזאת.

### 3. בדיקה

```
/thesis-check ssec:PrS_Method            סקריפט בלבד, שניות, בלי עלות
/thesis-check ssec:PrS_Method deep       + משלב, בהירות וזרימה
/thesis-check ssec:PrS_Method cite       + הציטוטים מול המאמרים
/thesis-check ssec:PrS_Method fit        + איך זה משתלב בפרק
```

כל דוח ממספר את הממצאים.

### 4. תיקון

```
/section apply ssec:PrS_Method 2 5 7
```

מיישם רק את הממצאים שבחרתי מהבדיקה האחרונה של אותו תת-פרק. שינוי סדר פסקאות או נגיעה מחוץ לתת-הפרק מוצגים קודם לאישור.

### שתי דרכי עבודה

- **מלאה**, לתת-פרק חדש: `plan`, `write`, ואז `deep`, `cite`, `fit`, ו-`apply`.
- **מינימלית**: כותבים בצ'אט כמו תמיד, ואז `/thesis-check <label> deep` ו-`cite`. בלי תוכנית, הסוקר בודק את הזרימה לפי הטקסט עצמו.

## `/thesis-check` בפירוט

### יעד הבדיקה

| יעד | דוגמה |
|---|---|
| כל התזה | `/thesis-check` |
| פרק | `/thesis-check 9` |
| תת-פרק | `/thesis-check ssec:PrS_Method` |
| טווח שורות (רק `cite`) | `/thesis-check Content/7.LiteratureSurvey.tex:120-160 cite` |
| מאמר אחד לאורך כל התזה (רק `cite`) | `/thesis-check key Gajewski_2020 cite` |

נבדקים רק הפרקים ש-`Thesis.tex` טוען. טיוטות כמו `temp*.tex` או `*_new.tex` לא נבדקות.

### ברירת מחדל: הסקריפט

בלי מילה נוספת רץ רק `lint.py`. הוא לא מודל, ולכן לא עולה כלום ונותן אותה תוצאה בכל הרצה.

**מה הוא בודק:**
- **שגיאות ששוברות את המסמך:** label כפול, הפניה ל-label שלא קיים, מפתח ציטוט שלא קיים ב-bib, איור או טבלה בלי כיתוב או בלי label.
- **הפרות כללים:** נקודה-פסיק, איות אמריקאי, גוף ראשון, קיצורים (don't), פתיחות לא פורמליות (So, But), ראשי תיבות שנכתבו בלי `\ac`, `\ac` בכותרת או בכיתוב, `\ref` בלי המילה Figure, Table או Equation, הפניה כתובה ידנית ("Figure 3"), label עם רווח או בלי קידומת מוכרת, איור שלא מוזכר בטקסט, יחידות בתאי טבלה, ומונחים כמו fabric ו-stand-off.
- **לשיקולי:** משפטים מעל 35 מילים, פסקאות קצרות או ארוכות מדי, מילות הגברה (very, a lot).
- **NEEDCITATION:** כל הסמנים.

**פרופיל משלב:** לכל פרק אורך משפט ממוצע, שיעור סביל, שיעור זמן עבר ומילות הגברה, מול תת-הפרק המייחס. פרק שחורג מסומן. פרק קצר מדי להשוואה, כמו תקציר ריק, מסומן ולא נשפט.

### `deep`: משלב, בהירות וזרימה

סוקר אחד שקורא את הטקסט פעם אחת ובודק:

| נושא | דוגמאות |
|---|---|
| משלב | קטעים שהקול שלהם שונה מתת-הפרק המייחס, שפה מעריכה או רגשית, זמנים לא עקביים |
| זרימה | פסקה שלא מספקת את הטענה שתוכננה לה, מעבר חסר, חזרה, סתירה בין הטקסט לטבלה, סדר פסקאות |
| בהירות | מושג לפני הגדרה, כינוי בלי הפניה ("the two loads"), משפט שלא עומד בפני עצמו, פרוצדורה שאי אפשר לשחזר, "always" בלי הסתייגות, "changes sign" לא מדויק |
| פסקאות | פסקה שממשיכה את הקודמת אבל נפתחת כחדשה, שתי פסקאות שאומרות אותו דבר |
| ספרות | ממצא של מחקר אחר בלי ייחוס בגוף המשפט |
| איורים | הסבר בכיתוב במקום בטקסט, טקסט שחוזר על מה שהאיור מראה, "(c, d)" בלי פירוש |
| מינוח וסימנים | מקפים לפי תפקיד המילה, סימן שחסר ב-List of Symbols או בשימוש אחר |

עד 15 ממצאים, החשובים קודם. לכל ממצא: שורה, ציטוט, הסבר והצעת ניסוח באנגלית.

### `cite`: הציטוטים

לכל משפט עם `\cite`: עמוד במאמר, ציטוט מילולי ופסק.

| פסק | משמעות |
|---|---|
| נתמך | המאמר אומר את זה, באותו היקף ובאותה עוצמה |
| נתמך חלקית | בתנאים, בטווח צר יותר, או על גודל אחר. מגיע ניסוח מתוקן |
| לא נמצא | נקרא והטענה לא שם |
| המקור טוען אחרת | יש ציטוט שסותר |
| מקור משני | המאמר רק מצטט מישהו אחר |
| אין קובץ | אין PDF בתיקיית Papers. לא נבדק מהזיכרון |

ההתאמה בין מפתח bib ל-PDF היא לפי שם המחבר הראשון והשנה בשם הקובץ. כשההתאמה לא ודאית, מוצגת טבלה לאישור לפני הבדיקה.

### `fit`: התאמה לפרק ולתזה

רק על תת-פרק. בודק את ההבטחה בפסקת מפת הדרכים של הפרק, את הכניסה מתת-הפרק הקודם ואת היציאה לבא, הפניות פנימה והחוצה, ועקביות מספרים והגדרות עם שאר התזה.

### `needcite`: מקורות חסרים

```
/thesis-check needcite
/thesis-check 8 needcite
```

לכל סמן NEEDCITATION ולכל מפתח שחסר ב-bib: עד שלושה מאמרים מתיקיית Papers, עם עמוד וציטוט. לא מוסיף שום ציטוט. מאמר שאין לו רשומה ב-bib צריך להוסיף ל-`bibliography.bib` לפני שמצטטים אותו.

### `build`: קומפילציה

```
/thesis-check build
```

הפעם היחידה שהתזה מקומפלת. `latexmk` עם biber, קריאת הלוג (שגיאות, הפניות וציטוטים לא מוגדרים, labels כפולים, קבצים חסרים, overfull מעל 10pt), ובדיקה חזותית של עמודים בעייתיים בלבד, עד כעשרה.

## משלב אחיד

תת-הפרק `ssec:Single_Obstacles` בפרק 7 מוגדר ב-CLAUDE.md כייחוס, בשורה `Register reference:`.

- הסקריפט מייצר ממנו **כרטיס משלב**: הכללים, הפרופיל ושמונה משפטים לדוגמה. הסוקר קורא את הכרטיס ולא את תת-הפרק כולו.
- הכרטיס נוצר מחדש לבד כשתת-הפרק משתנה.
- להחלפת הייחוס: לשנות את השורה ב-CLAUDE.md.

## מטמון

בתיקייה `.claude/cache/` של התזה. נוצר ומתעדכן לבד, לא עורכים אותו:
- `register_card.md`: כרטיס המשלב.
- `papers/`: הטקסט של כל מאמר בתיקיית Papers. מחולץ פעם אחת, ובהמשך רק מאמרים חדשים או שהשתנו. `cite` ו-`needcite` מחפשים בו.

ספר ארוך שמצוטט הרבה אפשר לרשום גם עם `/ref add`, כדי שיהיה זמין לכל הסוכנים בפרויקט.

## עבודה חסכונית בטוקנים

- **ברירת המחדל לא עולה כלום.** להריץ אותה הרבה.
- **`deep`, `cite` ו-`fit` על תת-פרק**, מיד אחרי שכתבתי אותו. פרק שלם או כל התזה רק לפני הגשה.
- **`cite` על טווח שורות** כשאני לא בטוח במשפט אחד.
- בהרצת `deep` על כל התזה, Claude אומר כמה סוקרים ירוצו לפני שהוא מתחיל.
